## F-1 (priority): wrapped tokens overlap the context words

**Mechanism.** The context words sit at `top: 22%` / `bottom: 22%`, centred and shrink-to-fit
(`styles.css` `.context-word`). A wrapped token is absolutely centred at 90% frame width
(`.wrapped-long-word`). Context words move into reserved strips only under
`.scrolling-long-text`, and that applies only when `shouldScrollWord` finds the wrapped height
greater than the **full** frame `clientHeight` (`app.js` `fitDisplayedWord`). Any wrapped
height between the context-word gap and the full frame height therefore collides.

Measured with context ON, large word size, viewport 1400×950 and 390×844, all four combinations
of focus mode × focus letter (`runs/overlap.json`, `runs/overlap-table.txt`). Rectangles are
`x / y / width / height` in CSS px. Context rectangles are the text ink (Range) boxes. "Overlap"
is the intersection of that ink with the visible word box.

## F-2: W6.1 never runs on frames 912 px or wider (pre-existing, identical on master)

`.word-display` has `max-width: min(820px, 94%)`. `fitDisplayedWord()` returns early when the
display's bounding rectangle satisfies `rect.width <= frame.clientWidth * 0.9`. The rectangle is
clamped to 820 px while the content overflows, so once `0.9 × frameWidth ≥ 820`
(frameWidth ≥ 912) every token "fits" and is never shrunk, wrapped or scrolled
(`runs/focus.json`, `runs/extra.json` `wide`).

| Build | Mode | Last viewport fitted (frame) | First viewport not fitted (frame) | Real 45 at first | W×2000 at first |
|---|---|---|---|---|---|
| branch = master | normal | 1707 px (911) | **1708 px (912)** | 128 px, overflow | 128 px, overflow |
| branch = master | focus | 995 px (911) | **996 px (912)** | 99.6 px, overflow | 99.6 px, overflow |

Examples: at 1920×1080 normal mode, the real word is 128 px with frame scrollWidth 2909 >
clientWidth 1124, and W×2000 has scrollWidth 257250 (`shots/normal-1920-branch-2000.png`). At
1400 focus mode the real word is 140 px, content 3181.7 px in a 1316 px frame
(`shots/focus-1400-branch-45.png`, identical to `shots/focus-1400-master-45.png`).

So F1 (the W4.5 overflow) is still present on the branch for wide frames, exactly as on master.
W6.1 requires breaking a token that "still exceeds the reader frame's width at the existing
10 px fitting floor", and W×2000 at 1920 qualifies. But a fix inside `fits()` would also change
how real words that are clipped today render, which W6.1's "renders exactly as before" protects.
That conflict is Marcus's call (D2). Codex's matrix (1400 normal, 390) did not reach these frames;
its focus-mode collision check passed only because nothing is fitted there.
