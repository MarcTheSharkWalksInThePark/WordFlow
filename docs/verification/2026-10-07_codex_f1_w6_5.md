## Recon — recorded before implementation

The prior candidate makes .word-display a wrapped block in the .reader-frame grid.
Its intrinsic height contributes to the reader-panel's minmax(280px, 1fr) row and the
frame's auto-sized grid track. At 390 px the 2000-W block therefore grows frame clientHeight
from 278 to 704. Existing overflow:hidden does not prevent intrinsic grid growth.
The implementation will take only wrapped tokens out of grid flow with absolute positioning;
normal-token grid layout remains intact and supplies the normal frame height.

scheduleNext advances one index, renders, saves and schedules the existing wordDelay.
pause clears reading/countdown timers and updates the controls without re-rendering the word.
play starts the existing 3-2-1 countdown; startReading sets playing and schedules advancement.
seekTo is the common manual/progress/navigation path; it renders and saves without splitting
the word. Countdown has its own existing active flag and renders countdown numerals instead
of the token. Auto-pause must run only after an actual token is fitted while playing.

Focus mode changes normal frame minimum height and word font size, then renders. Context
words are absolutely positioned at 22% from top/bottom; a scrolling token needs separate
reserved strips to avoid overlap. The note must occupy its own strip. resize already invokes
fitDisplayedWord; a browser orientation change that changes viewport size triggers this path.

## Implementation choices — proposed before coding

- Reuse the W6.1 predicate/wrapping from candidate.patch, retaining the 10 px floor and no
  visual hyphens. Absolutely position wrapped tokens so they cannot grow the grid.
- Compare wrapped natural content height strictly with normal frame clientHeight. Only excess
  enables a vertically scrolling word display; reserve strips for context and the exact note.
- Call existing pause when a scrolling token is reached during playback. A transient DOM
  marker records that the displayed token caused that pause, allowing Play to advance one
  existing navigation step before the normal countdown. No separate playback state or resume
  field is introduced. Loading/leaving the token clears that presentation marker.
- Make the scrolling word display a named, keyboard-focusable region. Native vertical touch,
  wheel and keyboard scrolling; horizontal navigation shortcuts stay available. Space on the
  focused region scrolls it, while Space elsewhere keeps its existing playback shortcut.

## Final implementation choices and outcome

Implementation choices: wrapped tokens are absolutely positioned at 90% frame width,
with overflow-wrap:anywhere and no visual hyphens. Only wrapped focus-letter spans become
inline. Normal tokens retain their existing grid layout, classes, fitting search and font floor.
shouldBreakWord requires fontSize <= 10 and measured width > frame clientWidth. The existing
12-step fitting search starts at 10 px, floors the fitted result, and never goes lower.
shouldScrollWord requires wrapping and natural content height > normal frame clientHeight,
strictly, without an epsilon. The height includes the DOM's scrollHeight and bounding rectangle.

The scrolling class reserves 52 px above and 96 px below; previous/next context and the exact
note occupy separate strips. Focus rails are hidden only for scrolling tokens. The scroll region
has tabindex=0, role=region, accessible name Long text and the note as its description. CSS
provides native vertical wheel/touch/keyboard scrolling, horizontal overflow suppression and
touch-action:pan-y. The browser checks prove all text is reachable rather than merely hidden.

Auto-pause calls pause(), including its existing timer cancellation and elapsed-time handling.
A transient data-long-text-paused DOM marker acknowledges that pause on the current index.
Play uses seekTo(index+1), then the existing countdown/startReading path. There is no new
state.* playback flag or stored resume field. Manual arrival remains paused until Play starts
the existing countdown; playback then pauses on the long token. Loading another source,
leaving the token or rendering countdown clears the marker, note, scrollTop and layout state.
Resize removes the scroll constraint to remeasure natural content, then restores the current
scrollTop only if the token still needs scrolling. A resize back to a fitting frame clears it.

No STOP condition occurred in the tested matrix. The previous mandatory STOP report and
candidate evidence are retained unchanged; W6.5 authorizes this subsequent implementation.
F1 is implemented locally under W6.1/W6.5, pending independent review. No protected proxy,
server, Functions, R59, push-gate, vendor, _headers or CSP file changed. No package installed.
